# frontend-crates agent instructions

- Before conformance work, read `conformance/README.md`, "Local current captures and bundled history". Keep authored inputs/GOLDEN and generic current YAML local. Historical Unified and legacy evidence belongs in bundled `conformance/historic/`; latest parser tests and publication must not open it. New captures publish independent immutable evidence and update only their latest family YAML; never rewrite the baseline inventory or merge a shared current index.
- The public version of the Unified conformance report is https://ai-dynamo.org/frontend-crates/?tab=tab-unified. After conformance fixture, parser, table-model, renderer, or conformance-documentation changes, follow [Generate the latest or history report](conformance/README.md#generate-the-latest-or-history-report) to regenerate the local report, then inspect `conformance/CONFORMANCE_v2.html` over HTTP before reporting completion. Do not stage or commit the generated HTML unless explicitly requested.
- A request to port, convert, or add a model family to `UnifiedParser` means a full conversion. `UnifiedParser` and its shared scanner must become the only parser state machine for that family. Remove the old bespoke v2 parser state machine; retain a legacy `ToolParser` entry point only when external callers still require it, and make it a thin projection of the same `UnifiedParser` events. Do not report a factory or registry entry as a conversion while a second family-specific buffer, scanner, drain loop, or grammar owner remains.

- Before adding conformance cases, inspect every registered family and author family-native inputs and expected outputs wherever the behavior applies. Explain grammar or mode exclusions; a bug found in one family does not justify family-only coverage. Use numeric Unified groups for shared behavior and named family sections for grammar-specific cases, preserve published IDs, and inventory every new conformance ID with its meaning and applicable families in the PR description.

- Contributor work edits parsers and authored inputs/GOLDEN, runs latest tests, and generates the latest report. Historical backfills are administrator work. Capture/history edits require administrator approval of the current PR head; authored inputs/GOLDEN do not.
