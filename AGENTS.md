# frontend-crates agent instructions

- Before conformance work, read `conformance/README.md`, "Latest captures and retained history", and `docs/CONFORMANCE-LATEST-PLAN.md`. Latest YAML lives beside unchanged versioned captures under `conformance/fixtures-unified-v2/families/<family>/<implementation>.yaml`. Latest tests and generation must not open historical captures or archives. No backfill is needed; versioned v2 removal, historical moves, and compression belong in later PRs.
- The public version of the Unified conformance report is https://ai-dynamo.org/frontend-crates/?tab=tab-unified. After conformance fixture, parser, table-model, renderer, or conformance-documentation changes, follow [Generate the latest or history report](conformance/README.md#generate-the-latest-or-history-report) to regenerate the local report, then inspect `conformance/CONFORMANCE_v2.html` over HTTP before reporting completion. Do not stage or commit the generated HTML unless explicitly requested.
- A request to port, convert, or add a model family to `UnifiedParser` means a full conversion. `UnifiedParser` and its shared scanner must become the only parser state machine for that family. Remove the old bespoke v2 parser state machine; retain a legacy `ToolParser` entry point only when external callers still require it, and make it a thin projection of the same `UnifiedParser` events. Do not report a factory or registry entry as a conversion while a second family-specific buffer, scanner, drain loop, or grammar owner remains.

- Before adding conformance cases, inspect every registered family and author family-native inputs and expected outputs wherever the behavior applies. Explain grammar or mode exclusions; a bug found in one family does not justify family-only coverage. Use numeric Unified groups for shared behavior and named family sections for grammar-specific cases, preserve published IDs, and inventory every new conformance ID with its meaning and applicable families in the PR description.

- A case or rendered column that is applicable to only one parser family must NEVER appear in a generic section. Put it in a named family-specific section, including after variant aggregation. Before classifying a case as family-specific, inspect every registered family and add native inputs and independent expected outputs wherever the behavior applies. Missing captures do not make an applicable family inapplicable; retain them as missing evidence. Preserve published case IDs when changing display placement.

- Contributors edit parsers and independently authored inputs/GOLDEN, recapture affected latest Dynamo v2 snapshots, run tests, and inspect the report. CI replays current native Dynamo v2 cases: GOLDEN differences warn; differences from recorded latest YAML fail. Capture changes use normal PR review. Preserve historical evidence and request/provenance bindings; historical and peer captures are not replayed against current parser code.
- Back-capture is useful but optional; no need to back-capture every historical version. Follow the [historical back-capture policy](conformance/README.md#historical-back-captures) and state which versions were actually run.
